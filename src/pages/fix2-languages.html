Languages: add one without losing another

Adding a language should never take one away, and the 🌐 key should never leave SmarType. The language list shows what's really in use, suggests the right languages for India, and lets people pick a layout.

Why English disappears

On a fresh install English is not saved as a language: the keyboard falls back to it when the list is empty. That's why the list shows "No keyboard languages yet" (L1). Adding Hindi saves Hindi as the only entry, so the fallback stops and English is gone (L2). Why 🌐 then opened another keyboard app isn't explained by the code: with the default setting and one language, that key turns into the emoji key (UtilityKeyPolicy.kt). It may have been the "switch keyboard app" setting for that key, or Android's own keyboard-switch button. Reproduce it on a device before fixing that part. Fix for the language list: on first launch, save the language in use (English, QWERTY) as a real entry, and migrate existing users the same way when their list is empty.

Acceptance criteria

  • On a fresh install, the Languages list shows English (US), QWERTY, marked default.
  • Adding any language never removes or replaces another, and doesn't change the default.
  • With two or more languages, tapping 🌐 never opens another keyboard app, unless the user set that key to switch keyboard apps.
  • Long-press on 🌐 lists SmarType's languages first; other keyboards only through "Other keyboards…".
  • On a phone set to India, Hindi, Telugu, Tamil and Bengali appear in Suggested before any English variant.
  • Each language row opens a sheet with Make default and Remove (and layout when there's a choice); Remove confirms with a dialog; the last language can't be removed.
  • Rows can be reordered; the first row is the default.
  • After switching to a language without a dictionary, no English suggestions appear.
  • Existing users whose list was empty see English saved after the update, with nothing else changed.
