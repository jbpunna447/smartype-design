First launch and setup

Get the keyboard working first, let people try it, and ask for sign-in when it's worth it.

New screens are drawn at real size: 1 px = 1 dp on a 360 × 800 dp phone. Open "Spec" under any screen for sizes, tokens and icons.

The problem

A new user reads four generic intro pages and a legal paragraph, then has to decide on sign-in before SmarType is even their keyboard (O1, O2, O3).

The sign-in screen talks about "Firebase Authentication" and "account-backed features" and gives no reason to sign in. The setup step shows a switch that isn't one and repeats the header text (O5). A failed sign-in carries on as if it worked, and the first thing a signed-in user sees is a toast telling them to sign in (O4).

Which keyboard the pictures name

The pictures show SmarType next to the keyboard the phone uses now, so the Android screen looks the way the user is about to see it. Not every phone has Gboard: Samsung phones use Samsung Keyboard, and some makers ship their own.

The app can read the keyboard in use directly, so a guess from the phone's maker is only a fallback.

OrderHowResult
1. The keyboard in use nowAndroid 14 and later: InputMethodManager.currentInputMethodInfo. Older: Settings.Secure.DEFAULT_INPUT_METHOD, then the service's info from PackageManager. Name from loadLabel(), icon from loadIcon(). The manifest already queries keyboards (android.view.InputMethod), and InputMethodUtils already reads these settings.Exact name and icon, including a keyboard the user installed (SwiftKey, Bobble, Indic Keyboard).
2. If that fails: the maker's usual keyboardBuild.MANUFACTURER (and Build.BRAND for Redmi, POCO, iQOO), lower-cased, looked up in the table below. Used only when the table says High or Medium.Close, not certain: the user may have changed keyboards, and the same maker ships different keyboards by region.
3. Otherwise"Your keyboard" with the keyboard icon.Always true, just less familiar.

Done when

  • A new user can enable and choose SmarType without seeing a sign-in screen.
  • At most two intro pages, and no "Page X of Y" text.
  • No onboarding screen mentions Firebase, Firestore or "account-backed features".
  • Each screen has one primary button, full width at the bottom; other actions are text buttons.
  • Setup cards show status badges, not switches; the action button is inside the active card.
  • Each active step shows a moving picture of the Android screen the user is about to see; it has no label, and tapping it does the same as the step's button.
  • The pictures name the keyboard this phone uses now (Samsung Keyboard on a Samsung phone), never a fixed "Gboard"; the name is never sent or logged.
  • The pictures sit on a raised surface (white in light theme) with a 1 dp outline, with no tinted rows inside.
  • Coming back from Android settings advances setup without a tap.
  • Skipping sign-in leaves a working keyboard; signing in later from ✦ works the same way.
  • After signing in, the user sees "Signed in as …" and never a "Sign in" message.
  • The number of free AI tries shown comes from the server (AI_FREE_TRIAL_LIMIT); it's a one-time trial, not monthly.
