TalkBack and screen readers

Everything on the keyboard can be found, heard and used without looking, including typing.

New screens are drawn at real size: 1 px = 1 dp on a 360 × 800 dp phone. Open "Spec" under any screen for sizes, tokens and icons.

The problem

In the review, Android's accessibility tree didn't show the AI or Translate panels or their buttons (A8).

The code today: the panels set pane titles, headings, live regions and spoken labels (AiOverlay.kt), so the review's tool probably read only the app's window, not the keyboard's. That still needs a check with TalkBack on a phone.

The keys are the bigger gap. They're drawn as one surface that reads raw touches, with no touch exploration, so with TalkBack on, typing likely doesn't work at all. Android's own keyboard solves this with "lift to type": slide to find a key, lift to type it.

What people need

NeedWhy
Type without lookingSlide a finger over the keys to hear them; lift to type. No double-tap per letter.
Find every buttonSwipe through the smartbar, suggestions and panels in a predictable order.
Know what changedHear "Rewrite ready", "Replaced", "Corrected to the" without moving focus.
Get back easilyBack always returns to the keyboard and to the button that opened the panel.
Keep passwords privateIn password fields keys are read as "dot" unless the user turned on Speak passwords.

Done when

  • With TalkBack on, a user can type a sentence by sliding and lifting, and hears each key.
  • Swiping goes through the smartbar, Mic and suggestions in the order shown, with the names in the table.
  • Every panel says its name when it opens, and focus lands on ‹.
  • Results, errors, Replace and autocorrect are announced without moving focus.
  • Password-field keys are read as "dot" unless Speak passwords is on.
  • Checked on a phone with TalkBack at font scale 1.5, in light and dark.
