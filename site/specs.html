Write and Voice mode

Two features that came out of the end-to-end UX review: one place to draft, polish and send text, and SmarType's own dictation that turns speech into finished text in one step.

25 Oct 2026Based on SmarType 0.12.0 (main @ c3d86d39c)Related: UX review findings N1–N3, D1, D2, A9–A11

Write

Notes and playground in one place

Why

People already use SmarType to draft text they then paste elsewhere: an email, a reply, a post. Today that job is split across Quick Notes, the scratchpad, the floating bubble and the "Try out your setup" boxes in Settings. The review found five names for one feature, a "Saved" label before anything is saved, Save emptying the editor, and no Copy, Share or AI in notes (N1–N3).

Write replaces all of these with one editor and one list of drafts.

Goals and scope

GoalsNot in this version
  • One name everywhere: Write for the editor, Drafts for the list.
  • Draft, rewrite, translate, dictate, then copy or share, without leaving the screen.
  • Never lose text: autosave, honest status, undo after every AI change.
  • Reach it from Home, the keyboard, the floating bubble and Android's Share menu.
  • Keep every existing Quick Note.
  • Cloud sync of drafts between phones (needs a separate privacy decision).
  • Rich text, images or attachments.
  • Sending directly through email or chat apps (we use Android Share).
  • Folders, tags or sharing drafts with other people.

Screens and flows

1. The Write editor

  • Top bar: back, the draft's title (first line, or "Untitled draft"), status, overflow (Duplicate, Delete, Drafts).
  • Template chips on an empty draft only: Blank, Email, Reply, Message, Post. A template inserts a short scaffold (for Email: "Hi [name]," / blank line / "Thanks,") with the first placeholder selected.
  • Editor: full height, SmarType keyboard, normal selection handles.
  • Status line under the editor: "Saving…", "Saved 11:31", or "Couldn't save · Try again". Word and character count on the right.
  • Action bar above the keyboard: Rewrite, Translate, Dictate, Copy, Share. When the keyboard is hidden it sits at the bottom of the screen.

2. Saving

  1. Every edit schedules a save 800 ms after the last keystroke. Leaving the screen, switching drafts, Copy, Share and any AI action save immediately first (same rule as today's flushForSwitch).
  2. The status says "Saving…" while a write is pending and "Saved hh:mm" when the stored text equals the editor text.
  3. There is no Save button. A blank draft that the user leaves is discarded, not listed.
  4. If a write fails, the status turns into "Couldn't save · Try again" and the text stays in the editor.

3. Copy, Share, and return to the app

  • Copy: copies the whole draft, or the selection if there is one. Toast "Copied". The clipboard entry is marked sensitive (ClipDescription.EXTRA_IS_SENSITIVE) so Android doesn't show a preview.
  • Share: Android share sheet with the plain text.
  • Opened from the bubble or the keyboard: the Copy button becomes Copy and close. It copies, saves and closes Write, so the user lands back in the app they came from and can paste.

4. Drafts list

  • Newest first. Each row: title (first line), second line as a preview, relative time ("11:31", "Yesterday", "12 Oct").
  • Search appears at 6 or more drafts (today's rule).
  • Swipe left to delete, with "Deleted · Undo" for 5 seconds.
  • "New draft" button at the top.
  • Empty state: "Your drafts will show up here. Start one from Home or the keyboard."

5. Keyboard Drafts panel

  • Opened from the Notes icon on the toolbar. Shows the 10 most recent drafts.
  • Tap a draft to insert it at the cursor in the current app (commit at the cursor only; never replace existing text).
  • "Open in Write" opens the full editor with the current draft.
  • Back returns to the letter keys (review finding A9).

AI and voice in Write

  • Rewrite and Translate open the same AI sheet the keyboard uses, but as a bottom sheet in the app. Scope is the selection if there is one, otherwise the whole draft. The scope shows as a chip ("Whole draft · 42 words").
  • Results use the existing tasks (AiTask.Rewrite, translate) through AiEngine, with the same quota, App Check and BYOK rules. No new backend work for v1.
  • Replace changes only the scoped range and pushes an undo step. A bar shows "Replaced with Professional · Undo" for 6 seconds. Undo is also in the editor's undo history.
  • Long drafts: the AI sheet warns above 2,000 words ("Long text may take longer") and the server's limits apply.
  • Dictate opens Voice mode (below) with its output going into the draft at the cursor.

Data and migration

  • Drafts stay on the phone only, in the existing QuickNotesDatabase (Room). No Firestore, no backup to the server in v1.
  • Schema: add updatedAt (if missing), templateId (nullable) and origin (home, keyboard, bubble, share) to the note table. One Room migration; no data is rewritten.
  • Migration on first launch: today's scratch draft becomes the newest draft if it isn't blank. Every saved note becomes a draft with the same text and time. Nothing is deleted.
  • Android Auto Backup: keep the database excluded unless the owner decides otherwise (drafts can be private).
  • Rename strings: Quick Notes → Write, scratchpad / Scratch draft / Saved note → draft. Keep the old route and deep link ui://smartype/settings/quick-notes working as an alias.

Voice mode

Speak, and get finished text

Why

Today the mic key calls switchToVoiceInputMethod() in FlorisImeService.kt, which hands the user to whatever voice keyboard is installed, usually Google voice typing. In the review:

  • SmarType's toolbar, styles and AI disappear while dictating (D1).
  • It gave up after about 3 seconds of silence: "Didn't catch that" (D1).
  • A 60-word dictation came back as one run-on sentence with no punctuation and about 6 misheard phrases, including SmarType's own "AI rewrite" as "aiv ride" (D2).
  • Getting clean text takes four steps: dictate, come back, open AI, rewrite.

Voice mode keeps the user inside SmarType: speak with pauses, see the words live, get cleaned-up text (optionally in a writing style), insert.

Goals and scope

GoalsNot in this version
  • Dictation inside the SmarType keyboard; no switch to another keyboard.
  • Natural pauses don't end the dictation.
  • One tap from speech to clean text: punctuation, sentences, fillers removed, self-corrections applied.
  • Optional writing style in the same step (Professional, Casual…).
  • Hindi + English mixed speech in v1 (via the recogniser's language support).
  • Audio never leaves the phone in v1.
  • Always-on listening or a wake word.
  • Voice control of other apps.
  • Saving audio recordings.
  • Server-side speech recognition (possible later, needs a decision).
  • Speaker identification or meeting transcription.

Keyboard flow

  1. User taps the mic on the toolbar (or long-presses space, configurable). The letter keys are replaced by the Voice panel; the text field stays visible above.
  2. First use only: a short explainer ("SmarType listens only while this panel is open. Audio stays on your phone.") and the Android microphone permission (see permission).
  3. Panel shows Listening: live transcript, a level meter, a timer, the language chip (from the active keyboard language) and the output chip (Exact, Cleaned, or a style).
  4. The user speaks, pauses, speaks again. The transcript keeps growing; a pause shows "Paused · still listening".
  5. User taps Done (or stays silent past the stop timeout). The panel shows Tidying up… while the clean-up runs.
  6. Review: the cleaned text, with "Show original" to compare. Buttons: Insert (primary), Keep talking, Discard. Output chips can be changed here and re-run the clean-up without speaking again.
  7. Insert commits the text at the cursor and returns to the letter keys. The suggestion row shows "Inserted · Undo" for 6 seconds.

Back, or the ABC key, at any point returns to the letter keys. If something has been transcribed, Back asks inline: "Insert what you said?" with Insert and Discard.

Why the live words stay in the panel, not in the text field. Writing partial results into the other app's field means repeatedly replacing text we don't fully control, which is one of this repo's risky areas (editor text changes). Keeping the transcript in the panel and committing once on Insert means the app's text is touched exactly once, at the cursor. An optional "Type as I speak" setting can come later.

Pauses and stopping

  • A silence shorter than the stop timeout is a pause, not the end. Default timeout: 8 seconds; setting: 4, 8, 15 seconds or "Only when I tap Done".
  • Android's recogniser ends a session on silence by itself. Voice mode restarts it immediately and stitches the segments into one transcript, so the user never sees the gap.
  • Each segment's final result replaces its own partial text; earlier segments are not re-recognised.
  • Hard limit: 5 minutes per dictation, with a notice at 4:30.
  • Leaving the field, switching apps, an incoming call or the screen turning off stops listening and goes to Review with what was captured.

Clean-up and styles

OutputWhat it doesNeeds network / quota

  • Spoken commands (local, no AI): "new line", "new paragraph", "full stop / period", "comma", "question mark", "delete that" (removes the last segment). Shown as a small hint on first use.
  • If clean-up fails or the user is offline, Review shows the Exact text with "Couldn't tidy up · Try again", and Insert still works.
  • A custom vocabulary list (names, product words like "SmarType") is sent with the clean-up request to fix terms like "aiv ride".

Engine and architecture

Speech recognition

OptionProsConsUse
SpeechRecognizer.createOnDeviceSpeechRecognizer() (Android 12+)Free, private, already on most phones, Hindi and English support, live partial resultsEnds on silence (needs restarts), accuracy similar to what we saw in D2, availability varies by phonev1 default

On-device Whisper (whisper.cpp, small or base model)Handles pauses and Hinglish better, no dependency on Google's recogniser40–150 MB download, CPU and battery cost, slower on older phonesv2, as an optional download
Server recognition through FunctionsBest accuracyAudio leaves the phone, cost per minute, new privacy termsNot planned; needs an owner decision

Components

  • VoiceSession (new, ime/voice/): owns the recogniser, restarts across silences, stitches segments, exposes a state flow matching the table above. Lives in the keyboard service scope, like AiRewriteSession, so a closed panel doesn't drop a request in flight.
  • Recognizer interface with an Android implementation now and a Whisper one later, so the UI doesn't change.
  • VoiceInputLayout (new panel, like the AI panel): uses the keyboard theme colours (rememberKeyboardPanelColors()), one scroll region, inline only (no popups in the IME).
  • Clean-up: a new managed task AiTask.CleanDictation(text, language, styleId?, vocabulary), mapped in :usage:firebase and handled by generateAiText with a new prompt in functions/src/prompts.ts. BYOK users go to their own provider as with rewrite.
  • Insert: commitText at the cursor through EditorInstance. Undo removes exactly the inserted range if the field hasn't changed since.
  • KeyCode.VOICE_INPUT opens the new panel. The old hand-off becomes a setting: "Use another voice keyboard" (off by default) for users who prefer Google's.

Privacy, quota and permission

  • Audio: never stored, never sent by SmarType in v1. Recognition runs on the phone.
  • Text: sent only for Cleaned or a style, only after the user taps Done, same as tapping Rewrite today. No logging of transcript or result.
  • Private fields: the mic is disabled in password fields and when the app requests no personalised learning; incognito follows the same rule as the AI panel (aiPrivacyBlockReason()).
  • Quota: one clean-up = one managed request, the same count as a rewrite. Free users see the remaining count on the output chip. Exact never uses quota.
  • Permission: add RECORD_AUDIO. A keyboard can't show the Android permission dialog itself, so the panel opens a small SmarType activity that asks, then returns to the keyboard. If denied twice, the panel links to app settings.
  • Mic indicator: Android's green mic dot shows while listening; the panel also shows "● Listening" so it's never ambiguous.
  • Play policy: update the Data safety form (audio processed on device, not collected) and the privacy policy.

  • V1Tapping the mic never switches to another keyboard (unless the user turned that setting on).
  • V2A dictation with three pauses of 3–5 seconds produces one transcript with all parts, in order.
  • V3"So um the delivery is on Tuesday, no sorry, Wednesday at three" becomes "The delivery is on Wednesday at 3." with Cleaned.
  • V4On a sample of 20 owner dictations, Cleaned output needs fewer manual edits than Google voice typing for at least 80% of them.
  • V5Insert adds text only at the cursor; Undo removes exactly that text.
  • V6Offline, Exact works and Insert is available.
  • V7The mic is disabled in password fields.
  • V8No audio file is written, and no log, analytics event or crash report contains transcript or result text.
  • V9Back or ABC from any state returns to the letter keys; it never hides the keyboard.
  • V10Works with TalkBack: state changes are announced ("Listening", "Paused", "Ready to insert").

Owner review needed

Under AGENTS.md, plans that touch these areas need the owner's plan review before any code:

Typed-text privacy. Voice adds a microphone permission and a new path for user text to the server (clean-up). Write stores more user text on the phone. Both must keep text out of logs, analytics and crash reports.
Firebase backend and managed AI quota. AiTask.CleanDictation needs a new prompt and task in functions/, quota rules and emulator tests.
Editor text changes. Voice Insert and Undo, and Write's keyboard insert, change text in other apps. Insert must touch only the cursor position; Undo only the inserted range.
Decisions for the owner: (1) Is "Write" the right name? (2) Should Cleaned be the default, given it uses one AI request each time? (3) Free users: how many voice clean-ups per day, or share the rewrite quota? (4) Keep the "Use another voice keyboard" option, or remove the Google hand-off entirely? (5) Drafts on the phone only, or plan encrypted sync?
