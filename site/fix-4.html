Errors that say what happened and what still works

Five places where SmarType shows the wrong message, an internal term, or the same error three times. Each gets one plain message with the real cause, what still works, and an action only when the action can help.

Root cause. Most of these strings aren't app copy: they're backend exception messages shown on screen as-is (for example FirebaseFunctionsPaymentCatalogBackend returns "Sign in before loading the billing catalog."). The fix is to map each error code to an app string, and never show a raw exception message to the user. Keep the technical reason in logs only.

Rules

  • One message per problem, shown once. No repeated titles and bodies saying the same thing.
  • Never show a raw exception or backend message to the user; map error codes to app strings.
  • No internal words on screen: verification token, billing catalog, Firebase, Firestore, managed AI, subtype.
  • Don't blame the app version unless the version really is the cause.
  • Show Retry only when retrying can work. Hide an action that can't work in this state (design system rule); disable it only when a step the user can take will enable it, and say which step.
  • Say what still works (typing, suggestions, voice).
  • "Sign in" messages only appear to signed-out users, and only after they tap something that needs it.
  • Persistent problems use an inline banner on the screen; one-off confirmations use a toast or snackbar.

Acceptance criteria

  • A signed-in user never sees a message asking them to sign in, on launch or after signing in.
  • After a successful sign-in, a toast confirms the account.
  • A failed or cancelled sign-in stays on the sign-in step, with Try again and Skip for now.
  • On a device that fails the Play check, Home, Premium and the AI panel each show one plain message; Upgrade and Replace are hidden; there's no Retry.
  • None of the words in the "no internal words" rule appear anywhere in the UI (checked with a string search).
  • Every user-facing error comes from strings.xml, not from an exception message.
